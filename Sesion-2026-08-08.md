## Sistema de membresía semanal (completado en sesión anterior, desplegado)

Tablas creadas (migration 038):
- `membership_plans`: moto $15, sedan $25, suv $35
- `driver_memberships`: registro de pagos por período

Columnas en `drivers`:
- `membership_status`: inactive | pending_approval | active | suspended
- `membership_expires`: DATE

Período semanal: Viernes → Jueves. Cron suspende conductores el sábado 04:01 UTC (00:01 Venezuela UTC-4).

Rutas:
- `GET /membership/status`, `POST /membership/initiate`, `POST /membership/submit`
- Admin: `GET /admin/memberships/pending`, `POST /admin/memberships/:id/approve|reject`

Pantalla móvil: `mobile/app/(driver)/membership.tsx`
El conductor selecciona tipo de vehículo (Moto/Sedan/SUV) antes de iniciar el trámite.

## Diagnóstico: login móvil "botón azul no hace nada"

Síntoma: presionar "Iniciar sesión" no produce spinner, no produce error, no redirige.

Causas descartadas:
- Bug wizard flag (driverWizardActive) → ya corregido en authStore.ts línea 79
- VPN / red WiFi bloqueando Firebase → no es el caso con Secure VPN activa

Causa más probable: **bundle de Expo en caché con código viejo**.

**Fix:** `cd mobile && npx expo start --tunnel --clear` y reabrir la app desde el QR nuevo.

Otros candidatos si el --clear no resuelve:
- Email no verificado en Firebase → el backend devuelve EMAIL_NOT_VERIFIED → authStore lo captura sin mostrar Alert → verifica en Firebase Console
- Usuario no existe en BD de producción → ejecutar `SELECT id, email, role FROM users WHERE email = 'pasajero1@vride.test'` en Railway SQL

## Admin panel

- Email admin: `admin@vride.app`
- Contraseña: variable `ADMIN_PANEL_PASSWORD` en Railway (NO está en el código)
- Lockout: 5 intentos fallidos → bloqueo 15 min en Redis
- Si bloqueado: limpiar con `DEL admin:lock:email:*` en Redis CLI de Railway
- El admin logeado en la app móvil queda atrapado en loop (layout lo devuelve a login) — el admin solo usa el dashboard web

**Why:** El sistema de admin usa contraseña propia (no Firebase) + búsqueda por email en PostgreSQL con rol `admin`.
**How to apply:** Si el admin no puede entrar, verificar primero que `ADMIN_PANEL_PASSWORD` existe en Railway Variables, luego que el usuario existe en la BD.
