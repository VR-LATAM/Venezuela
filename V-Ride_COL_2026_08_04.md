## 1. Origen del Proyecto

**V-Ride Colombia** (originalmente llamado **Verona Ride**) es una plataforma de transporte privado desarrollada por Edward Labrador para **ELITE GROUP - Integral Services LLC**.

- Especializada en adultos mayores, personas con discapacidad y pasajeros con necesidades especiales (segmento NEMT).
- Originalmente lanzada en Texas (EE.UU.), con arquitectura pensada para expansión nacional.
- Stack: React Native + Expo (mobile), Next.js (dashboard), Node.js + Express (backend), PostgreSQL + PostGIS (Supabase), Redis, Firebase, Stripe Connect.
- Estado actual: ~95+ features, 37 migraciones de BD, Stripe Live activo, ~982/1000 puntos.

---

## 2. Intención de Adaptación a Colombia

Se recibió un prompt de especificación técnica detallado con los siguientes módulos principales:

1. **Modelo financiero:** Cambio de comisión por viaje (19/18/17%) a membresía semanal fija de $50.000 COP para conductores (100% de cada viaje va al conductor).
2. **Pasarela de pagos colombiana:** Wompi / Bold / PayU — PSE, Nequi, Daviplata, tarjetas, Efecty.
3. **Tarifas Bogotá:** base_fare, cost_per_km, cost_per_minute en COP.
4. **Regulación colombiana:** SOAT, Revisión Técnico-Mecánica, Cédula de Ciudadanía, Licencia colombiana, Tarjeta de Propiedad.
5. **Seguridad:** Botón SOS con línea 123, PIN de confirmación de viaje.
6. **Dashboard:** Pestaña "Membresías y Recaudo", geofencing Bogotá + municipios aledaños.

### Lo que ya existe en el proyecto (no hay que construir desde cero):
- Botón SOS / emergencia
- Código PIN de confirmación de viaje
- Geofencing (infraestructura base)
- KYC de documentos de conductores (módulo base)
- Dashboard de admin con métricas

### Lo que requiere trabajo real:
- Modelo de suscripción semanal ($50.000 COP)
- Pasarela de pagos colombiana (Wompi, Bold o PayU)
- Moneda COP (cambio transversal)
- Tarifas Bogotá
- Panel "Membresías y Recaudo"

## 3. Decisión de Base de Datos

**Decisión tomada: Proyecto Supabase nuevo, independiente del de EE.UU.**

### Opciones evaluadas:

| Opción | Descripción | Veredicto |
|--------|-------------|-----------|
| A | Misma BD, schemas separados | Descartada — riesgosa |
| B | Proyecto Supabase nuevo | ✅ **Elegida** |
| C | Misma BD, columna `market` | Descartada — difícil de mantener |

### Razones para Opción B:
- Las 37 migraciones de EE.UU. tienen lógica de Stripe Connect, commission_rate, payout_schedules — no aplica en Colombia.
- El modelo de suscripción semanal requiere tablas nuevas sin sentido en EE.UU.
- Aislamiento total entre mercados.
- Cumplimiento con **Ley 1581 de 2012 (Habeas Data Colombia)** — equivalente colombiano al GDPR.
- Posibilita franquicia por ciudad (Bogotá, Medellín, Cali) sin interferencia.

## 4. Stripe en Colombia — Análisis

### Contexto:
El caso de uso es simple: cobrar **$50.000 COP semanales** a cada conductor. No es un marketplace, no hay flujos entre pasajeros y conductores por la app.

### Stripe en Colombia:
| Método | Soporte |
|--------|---------|
| Tarjetas Visa/Mastercard colombianas | ✅ Funciona |
| Suscripciones recurrentes (Stripe Billing) | ✅ Funciona |
| PSE | ❌ No soportado nativamente |
| Nequi / Daviplata | ❌ No soportado nativamente |

### Estrategia de pasarela de pagos recomendada para lanzamiento:

1. **Stripe** → tarjetas débito/crédito (ya integrado)
2. **Wompi** (de Bancolombia) → PSE + Nequi + Daviplata
3. **Efectivo** → admin activa la membresía manualmente (válido para lanzamiento inicial)

### Contexto de mercado colombiano:
- Nequi tiene más de 20 millones de usuarios en Colombia.
- Conductores de plataformas (Uber/InDriver) frecuentemente no tienen tarjeta de crédito pero sí Nequi o Daviplata.
- PSE lo usan más usuarios con cuenta bancaria tradicional.

### Pendiente por definir:
- ¿Se tendrá punto de atención física en Bogotá o será 100% digital?
- Preferencia de pago del público objetivo de conductores en Bogotá (tarjeta vs Nequi/PSE) — aún desconocida.
